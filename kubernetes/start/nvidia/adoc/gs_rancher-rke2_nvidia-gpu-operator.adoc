Graphics Processing Units (GPUs) provide unique capabilities for accelerating a broad spectrum of workloads, such as artificial intelligence and machine learning, scientific and engineering simulations, and many more.
Developing and deploying these workloads in containers on {k8s} clusters offers potential for improved portability, scale, and efficiency.
However, GPU resources are not automatically visible or accessible to workloads running in containers.

In this guide, you learn how to:

 * install the {nvidia-drv} on each {rke2-full} worker node

 * deploy the {nvidia-op} Helm chart on {rke2-full}

This guide covers the following:

* finding and installing the appropriate {nvidia-drv} for the {nvidia-org} GPU installed on the {rke2} cluster

* finding and deploying the appropriate version of the {nvidia-op} Helm chart

* Verifying the functionality of the {nvidia-op} software and the {nvidia-drv}

+
{rancher} provides a shell interface through the management web interface that includes tools like kubectl and Helm. 
This comes in the form of a non-persistent container running on the {rancher} {k8s} cluster. 
This approach provides numerous security advantages. 
Users must first authenticate through {rancher-full} before they can view or manage downstream clusters. 
This is more secure than providing users with kubeconfig files that don't require authentication and could get checked into a version control system or otherwise end up in the wrong hands.
In addition, any sensitive data saved in the shell session will be deleted when the container exits.

. On each GPU configured worker node, deterimine which GPU(s) are installed:
//
+
[source, console, subs="attributes+"]
----
sudo lspci -v | grep -i nvidia
----
//
+
. Find the latest "Data Center / Tesla" driver for "Linux x64 SLES 15" using "Any CUDA Toolkit Version" for the GPU(s) installed on your worker nodes at {nvidia-drv-url}[{nvidia-org} Driver Downloads].
+
[NOTE]
====
You can move the driver package to each of the GPU worker nodes in whatever way you wish. One way to do this is described below, but it certainly isn't the only way.
====
+
.. Click on the "View" button to see the details for the driver. 
+
.. Right click on the "Download" button, and select "Copy Link".
+ 
.. In a terminal window on each GPU worker nodes, download the package with `wget`. For example:
+
[source, console, subs="attributes+"]
----
wget https://us.download.nvidia.com/tesla/560.35.03/nvidia-driver-local-repo-sles15-560.35.03-1.0-1.x86_64.rpm
----
//
+
. Install the driver package:
[source, console, subs="attributes+"]
----
sudo rpm -i ./nvidia-driver-local-repo-sles15-560.35.03-1.0-1.x86_64.rpm
----
//
+
. Install the CUDA drivers:
+
[source, console, subs="attributes+"]
----
sudo zypper install cuda-drivers
----
+
. Reboot each GPU equipped worker node, one at a time:
[source, console, subs="attributes+"]
----
sudo reboot
----
+
. After each worker node has successfully rebooted, ensure the {nvidia-org} kernel modules have been loaded:
+
[source, console]
----
sudo lsmod | grep nvidia
----
+
You should see the `nvidia`, `nvidia_drm`, `nvidia_modeset`, and `nvidia_uvm` kernel modules have been loaded.

. Verify the `nvidia-smi` utility can communicate with the GPU.
+
[source, console, subs="attributes+"]
----
sudo nvidia-smi
----
